## 统一端点

bytestream 的全部文本模型均通过同一个 OpenAI 兼容端点调用：

```
POST https://aiapi.bytestream.com.cn/v1/chat/completions
```

请求体、响应体结构与 [OpenAI Chat Completions API](https://platform.openai.com/docs/api-reference/chat) 保持一致，
仅 `model` 字段取值决定实际路由到的供应商与模型档位（见各供应商系列页面的模型清单）。

## 统一鉴权

请求头携带：

```
Authorization: Bearer sk-xxxxxxxxxxxx
```

`sk-` 前缀可省略。令牌需要在「控制台 → 令牌管理」中绑定可访问目标模型的分组，否则会返回鉴权 / 额度类错误。

## 流式 / 非流式响应

- 非流式：`stream` 省略或为 `false` 时，返回完整 `chat.completion` 对象。
- 流式：`stream: true` 时，返回 `text/event-stream`，逐块推送 `chat.completion.chunk`，以 `data: [DONE]` 结束。

<Tabs items={['非流式请求', '流式请求']}>
  <Tab value="非流式请求">
    ```bash
    curl https://aiapi.bytestream.com.cn/v1/chat/completions \
      -H "Authorization: Bearer sk-your-token" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "<按供应商系列页面选择>",
        "messages": [{ "role": "user", "content": "你好" }]
      }'
    ```
  </Tab>
  <Tab value="流式请求">
    ```bash
    curl https://aiapi.bytestream.com.cn/v1/chat/completions \
      -H "Authorization: Bearer sk-your-token" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "<按供应商系列页面选择>",
        "messages": [{ "role": "user", "content": "你好" }],
        "stream": true
      }'
    ```
  </Tab>
</Tabs>

## 通用错误码

| 状态码 | 说明 |
| --- | --- |
| `200` | 请求成功 |
| `400` | 参数错误 · `invalid_request` |
| `401` | 令牌无效 · `invalid_api_key` |
| `402` | 额度不足 · `insufficient_user_quota` |
| `429` | 触发限流 · `rate_limit_exceeded` |
| `500` | 上游 / 网关内部错误 |

错误体统一为 `{"error": {"message", "type", "param", "code"}}`；各供应商系列如有特有错误码，会在该系列页面单独补充。

<Callout type="info" title="模型清单与命名说明">
  各供应商系列页面「模型清单」中列出的模型名（如 `gpt-5.6`、`claude-opus-4.8`、`claude-sonnet-5`、
  `deepseek-v4-pro`）为 **bytestream 对外提供的模型名**，对接方请求时 `model` 字段直接传入这些名称即可。
  这些名称通过「渠道 → 自定义模型」映射到具体上游模型，映射关系为运行时配置，不在代码仓库中，具体上游模型
  请以控制台「渠道管理」当前配置为准。
</Callout>
